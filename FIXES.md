## Как перенести изменения в существующий репозиторий

1. Сохрани незакоммиченные изменения отдельно, если они есть.
2. Открой терминал в существующем клоне репозитория (где находится .git).
3. Создай резервную ветку и удали старые отслеживаемые каталоги:

```powershell
git status
git branch backup-before-review-fixes
git rm -r --ignore-unmatch mavengraph .idea
```

4. Скопируй СОДЕРЖИМОЕ папки из архива в корень своего клона с заменой
   совпадающих файлов. Не помещай всю папку master внутрь репозитория.
   Каталог .git существующего клона сохраняется. Корневого mavengraph/
   после переноса быть не должно: пакет теперь в src/mavengraph/.
5. Установи пакет и проверь его из корня проекта:

```powershell
python -m pip install -e .
python -m unittest discover -s tests -v
python -m mavengraph --test-mode --package A --repository examples/diamond.json
```

6. Проверь diff и создай новый коммит:

```powershell
git add -A
git diff --cached --stat
git commit -m "fix(project): address repository review findings"
```

## Как исправить С6 — старое сообщение коммита

Новый корректный коммит не изменит сообщение старого ebad0c5.
Сначала найди его в своём клоне:

```powershell
git log --oneline --all
```

Если ebad0c5 присутствует в текущей ветке, запусти:

```powershell
git rebase -i --root
```

В открывшемся списке замени `pick` на `reword` в строке коммита ebad0c5.
Сохрани и закрой редактор. Затем введи сообщение формата
`type(scope): description`, описывающее именно изменения того коммита.
Например, `feat(graph): add Maven dependency graph` подходит, только если
тот коммит действительно добавляет граф зависимостей. Исправь аналогично
другие сообщения, если они тоже нарушают формат.

Перезапись сообщений меняет хеши коммитов. Резервная ветка сохраняет
прежнюю историю локально. Для уже опубликованной ветки после проверки
результата потребуется:

```powershell
git push --force-with-lease
```

Это обновляет историю удалённой ветки. Если в ней работают другие люди,
сначала согласуй с ними перезапись. Если Git сообщает об изменениях
удалённой ветки, не заменяй --force-with-lease на --force.
Резервную ветку публиковать не нужно.
Если ebad0c5 не найден, не переписывай историю наугад: сравни ветку
и репозиторий с теми, которые проверяет преподаватель.
